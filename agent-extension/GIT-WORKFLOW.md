# Git и worktree

| Ветка | Назначение |
|---|---|
| codex/bmad-business-analysis | Архив: исходный код, документы и история сохраняются |
| codex/agent-extension | Главная feature-ветка от origin/develop, интеграция агентского расширения |
| codex/<задача> | Отдельная история, рефакторинг, исправление или возврат к истории; создаётся от актуальной feature-ветки и сливается обратно в неё |
| develop | Получает всю feature после завершения разработки; отдельные истории напрямую не сливаются |

Каждая параллельная задача — отдельная ветка и Git worktree от feature. Рабочий каталог задачи — её worktree; чужие изменения сохраняются, общие Git-метаданные учитываются. Возврат к принятой истории начинается новой веткой от текущей feature, а не продолжением старой ветки. Новые имена используют `codex/`.

## Перенос из архива

Архив не сливается целиком. Код, необходимые настройки/тесты/зависимости и минимальная рабочая документация копируются выборочно; оригиналы сохраняются. Feature содержит окончательные факты без хронологии и обязательного чтения архива. Эти правила Git входят в переносимый комплект.

Для каждой корневой папки: анализ → список «перенести/оставить» → подготовка/реорганизация/проверка → подтверждение пользователя → копирование. Подтверждение одной папки не разрешает остальные. Код/настройки/тесты идут по умолчанию в рамках подтверждённой папки; отдельно обсуждаются документация/артефакты. Подготовка/коммит архива и создание feature-worktree не разрешают копирование.

Переносятся архитектура, действующие контракты/инструкции, ограничения проверенности и оставшийся план. Журналы, отменённые варианты, старые test-window/review/handoff остаются в архиве. Уникальное действующее правило из них извлекается в рабочий документ. Локальные credentials/машинные настройки не включаются в Git автоматически. После копирования проверить ссылки/совместимость кода с origin/develop; приёмка истории не присваивает PASS непроверенным сценариям.

## Завершение worktree

После слияния задачи ненужный worktree убирается штатным `git worktree remove`. Перед удалением проверить абсолютный путь, использование другими задачами, staged/unstaged/untracked/ignored файлы, незавершённые Git-операции и уникальные коммиты. Непроизводные локальные файлы сохранить с проверкой копии; кэш/сборки не уникальные исходники. Ветка/коммиты сохраняются. Не применять автоматически `--force`, `git clean` или рекурсивную очистку неизвестных каталогов.
