# Агентское расширение

Администратор находит заказ/чек в 1С по номеру, сервисному коду или фото, уточняет успешный диалог и явно поручает фискализацию. Ответ отражает подтверждённый исход или неопределённость.

## Требования

| ID | Результат |
|---|---|
| CAP-1 | Актуальный поиск branch+order; сумма только hint (AC-01–03) |
| CAP-2 | Guard текста/фото до main, допуск отдельно от полей (AC-02–04) |
| CAP-3 | Успешный контекст после idle/restart, одна активная операция (AC-05,13–14) |
| CAP-4 | Явная фискальная просьба+runtime/1С checks, без повторного эффекта (AC-06–07,21) |
| CAP-5 | Enqueue до202, Web PubSub итог/ошибка≤120 секунд от Send (AC-08–09,14) |
| CAP-6 | Только свои sessions/channels и допустимый branch (AC-10–11) |
| CAP-7 | Дубли/гонки/late не повторяют effects/старую операцию (AC-12–16) |
| CAP-8 | Ограниченное хранение/cleanup и telemetry без содержимого (AC-17–20) |
| CAP-9 | Telegram управляет listener/API внутри Connector без SCM/replay (AC-24) |

Не входят: своя прикладная БД/outbox/recovery, второй login, общая платформа с другой интеграцией, отдельный аудит, гарантированная доставка старого ответа. Реальные фискальные действия требуют отдельного безопасного согласования.
